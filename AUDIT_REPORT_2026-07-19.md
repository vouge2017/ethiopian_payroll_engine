## 2. Database & Data Integrity

**Verdict: Partially ready**

**Evidence:**
- Foreign keys exist on all critical tables (employee→company, payslip→employee, payroll_run→company, leave→employee, audit_log→company, filing_record→company).
- **SQLite does NOT enforce FKs.** Test: inserted a payslip for non-existent employee (id=99999) — succeeded on SQLite. PostgreSQL would enforce these.
- Multi-tenancy: `TenantQuery` raises `RuntimeError` if no `company_id` filter on tenant-scoped models. Verified: `Employee.query.all()` without context → blocked. Routes use `filter_by(company_id=_company_id())` consistently.
- **`set_tenant_context()` does NOT add a filter — it just bypasses the check.** Background tasks using this must manually filter by `company_id`. This is a design choice, not a bug, but it's behavioral enforcement, not structural.
- Money stored as `Numeric(12,2)` (Decimal), not floats. Verified in `models.py`.
- All `datetime` fields use `datetime.now(timezone.utc)`.
- Migration chain: 20 migration files, all have `revision`, `down_revision`, `upgrade()`, `downgrade()`. Chain integrity test passes (no cycles, single head).
- Soft delete: `SoftDeleteQuery` auto-filters `is_deleted=False` on `.all()`, `.first()`, `.count()`. Found and fixed one leak in department dropdown.

**What needs to happen:**
1. All testing must happen against PostgreSQL, not SQLite (critical — FK enforcement depends on it)
2. Document the `set_tenant_context` gotcha for background tasks

## 3. Security

**Verdict: Ready (strong)**

**Evidence:**
- **Passwords:** scrypt:32768:8:1 (Werkzeug default). Hash + salt, not reversible.
- **Sessions:** HttpOnly=True, SameSite=Lax, Secure=True (production). Idle timeout 30min, absolute timeout 8hr.
- **Auth:** MFA (TOTP) via pyotp. Password reset: token not in URL/flash, rate-limited 5/min, user enumeration fixed (identical messages).
- **CSRF:** Flask-WTF CSRFProtect on all forms.
- **XSS:** No `|safe` filter in templates. Jinja2 auto-escapes by default.
- **SQL injection:** No raw SQL string concatenation. Only `text('SELECT 1')` for health check.
- **PII:** `bank_account` and `tin` encrypted with AES-256 (`EncryptedType` in SQLAlchemy-Utils). Encryption key from `DB_ENCRYPTION_KEY` env var.
- **Rate limiting:** Login (5/min), password reset (5/min), payroll approval (10/min), API (5-30/min). Flask-Limiter with configurable backend (memory default, Redis for production).
- **Tenant isolation:** Structural enforcement via `TenantQuery`. Verified: cross-tenant queries blocked without `company_id` filter.
- **API auth:** `api_token_or_login_required` decorator — Bearer token or session. 401 if neither.
- **Dependency scan:** Could not run `pip-audit` or `safety` (environment limitation). Manual review: no known critical CVEs in pinned versions.

**What needs to happen:**
1. Run `pip-audit` in CI/CD pipeline (not blocking, but should be automated)
2. Consider Redis for rate limiter in production (current in-memory is per-worker)

## 5. Regulatory / Compliance

**Verdict: Unverified**

**Evidence:**
- **Tax brackets:** Proclamation No. 1395/2025 — 0%, 15%, 20%, 25%, 30%, 35%. Threshold ETB 2,000. Personal relief ETB 150. **Source: hardcoded in `tax.py` DEFAULT_BRACKETS. No link to actual ERCA document.**
- **Pension rates:** 7% employee / 11% employer on basic salary. **Source: hardcoded in `pension.py`. No link to actual POSSA document.**
- **Configurability:** Tax rules are DB-configurable via `TaxRule` model with effective dates. If rates change, admin can update via UI without code deploy. Cache invalidation exists (5-min TTL + manual `invalidate_tax_cache()`).
- **ERCA filing format:** Generated as Excel via `openpyxl`. **Has never been tested against an actual ERCA submission.** Format is assumed from documentation.
- **Data retention:** `retention.py` exists with configurable windows (365 days for payslips, 90 for drafts, 180 for uploads). Ethiopian law requires 10 years for tax records. **Current default (365 days) may be legally insufficient.**
- **Filing history:** Just built — `FilingRecord` model tracks when filings were made, by whom, with confirmation numbers. Audit-logged.

**What needs to happen:**
